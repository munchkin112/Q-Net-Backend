# 수집 데이터 DB 반영 결과

확인일: 2026-10-06. 사용자의 DB 반영 요청에 따라 Render PostgreSQL에 실제 저장하고 별도 연결에서 검증했다.

## 저장 범위

| 자료 | 저장 위치 | 결과 |
| --- | --- | --- |
| 공식 종목 목록 | certificates | 기존 613종목 확인·유지 |
| 기술자격 시험 상세정보 | exam_information | 기존 510종목 확인·유지 |
| 기술자격 시험일정 | schedules | 기존 1,922행 확인·유지 |
| 전문자격 상세 수집 결과 | sources | 100건: 정상 56 / 빈 응답 36 / 실패 8 |
| 전문자격 계열별 일정 수집 결과 | sources | 37건: 정상 35 / 실패 2, 검증된 72단계 후보 포함 |
| 기존 DB와 다른 기술자격 일정 후보 | sources | 5종목 × 3회차 = 15건, 비교 필요 상태로 보관 |

신규 원문 보관은 총 152건이다. 빈 응답·실패 기록은 시험 상세정보가 아니라 수집 상태로 저장했다. 전문자격의 과목·기준·응시료 정규화와 계열별 일정의 종목·등급별 적용 확인은 아직 남아 있다. 현재 상세정보·일정 API가 자동으로 이 원문을 조회하지는 않는다.

## 기존 자료 보존과 검증

종목 목록의 DB 조회 시각은 준비 파일보다 최신이었다. 613종목의 코드·이름·분류·출처를 비교했고, 상세정보 510종목은 모든 입력 필드를 비교했다. 일정 1,922행 중 1,907행은 준비 파일과 일치했다.

나머지 15행은 건축기사(1630), 전기기사(1150), 전기산업기사(2140), 정보처리기사(1320), 정보처리산업기사(2290)의 실기 1·2·3회차다. 기존 API 응답에는 발표 표시 종료일이 있고, 준비한 공식 페이지 응답에는 빈자리 접수일이 있는 등 날짜·출처가 다르다. 어느 쪽을 덮어쓸지 추정하지 않고 후보 원문을 별도로 보관했다.

기존 사용자·프로필·종목·시험정보·일정 테이블은 변경하지 않았다. 원문 719파일의 저장 해시를 검증했으며, 이전 Windows 수집기에서 LF가 CRLF로 저장된 경우에는 줄바꿈만 복원하여 응답 해시도 대조했다. 전문 수집 원문 전체와 호출 메타데이터를 함께 저장했다.

- 최초 실행: 신규 152건, 저장 후 원문·해시 일치 152건.
- 재실행: 신규 0건, 원문·해시 일치 152건.
- 저장 전후 기존 테이블 건수와 준비 파일 대비 차이 목록 일치.
- 원문 변조·누락·Windows 줄바꿈·수집 상태 보존·기존 준비 검증 테스트: 9개 통과.

## 실행 및 확인 파일

```powershell
.venv\Scripts\python.exe -m research.apply_preparation
.venv\Scripts\python.exe -m research.apply_preparation --apply
.venv\Scripts\python.exe -m unittest research.test_apply_preparation research.test_preparation
```

기본 실행은 검증만 한다. `--apply`는 원문을 검증한 뒤 `sources`에 한 트랜잭션으로 저장한다. SQL의 종목 외래키는 기존 종목 ID에 연결하며 계열 일정은 계열 코드로 보관한다. 같은 출처 키·수집 시각은 중복 저장하지 않고, 원문이 다르면 전체 저장을 취소한다. 저장 후 별도 DB 연결로 내용을 재검증한다. 인증정보는 결과 파일에 기록하지 않는다.
