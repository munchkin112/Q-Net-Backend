# 시험 상세정보 연동

## 구현한 내용

공식 시험과목·합격기준·응시료를 Render DB에 저장하고 상세 조회 API로 제공한다. 자격증 검색은 613개 전체를 지원한다. 상세정보는 표본 10종목 검증 이후 기술자격 513개 전체를 대상으로 확대했다. 실제 저장·누락 종목은 [확대 결과](기술자격_상세정보_확대결과.md), 실행 방법은 [일괄 수집 설명](기술자격_일괄수집.md)을 참고한다.

산업안전기사(1431)는 기존 상세정보 호출·원문 변환·저장·조회 코드 수정 없이 처리됐다. 일정 API는 최초 요청과 1회 재시도 모두 시간초과가 발생했다. 이번 검증에서는 같은 종목의 Q-Net 공식 페이지를 새로 읽고 정기 3회차·필기/실기 6단계를 기존 날짜 검증과 저장 함수로 저장했다. 빈자리 접수 기간도 별도 필드에 보관했다. 공식 페이지 출처와 실제 원본 조회 시각을 기록했으며, 자동 Fallback을 구현한 것은 아니다.

검증 결과는 `research/industrial_safety_verification.json`, 상세정보 저장 결과는 `research/industrial_safety_detail_render_sync.json`, 일정 원본은 `research/responses/industrial_safety_current_page.html`이다. `research/industrial_safety_validation.py`는 이번에 저장한 공식 페이지를 읽는 검증용 실행 파일로, 일반 API 자동 수집 경로와 분리되어 있다. 실행은 `python -m research.industrial_safety_validation --apply`이며, 원본의 과거 조회 시각을 유지한다.

이번 `exam_information` 테이블은 시험정보만 저장한다. 보류한 응시조건 JSONB와 자동 응시자격 비교는 추가하지 않았다.

## 실행 순서

```text
DB에 저장된 종목 코드·이름 확인
→ 공식 상세정보 API와 수수료 API 호출
→ XML을 딕셔너리로 변환
→ 선택한 종목과 응답 종목명 대조
→ 취득방법 원문에서 시험과목·합격기준 구간 추출
→ 필기·실기 정보와 금액 검증
→ 미리보기 생성 또는 명시적으로 DB 저장
→ 상세 조회 API에서 저장된 자료 반환
```

복잡한 Agent나 새로운 라이브러리를 추가하지 않았다. API 호출은 기존 httpx 함수와 최대 1회 재시도를 재사용하고, 변환은 Python 함수·조건문·반복문으로 작성했다. 공식 정보에 HTML이 있을 때는 Python 기본 HTMLParser로 텍스트만 읽는다. 독스트링과 새 설명 주석은 한국어로 작성했다.

## 입력과 반환값

동기화 입력은 공식 코드 문자열이다. 기본값 `1320`은 정보처리기사다. DB에 없는 코드나 전문자격은 현재 동기화 대상에서 거절한다. 다른 기술자격도 옵션으로 조회할 수 있지만 원문 형식과 전체 필드가 검증되어야 저장할 수 있다.

HTTP 입력은 검색 API에서 얻은 내부 자격증 UUID다. 코드 `1320`을 UUID 자리에 넣으면 422가 발생한다.

```http
GET /api/v1/certificates?q=1320
GET /api/v1/certificates/{검색 결과의 id}
```

상세 응답은 기본 종목 정보와 `exam_information.subjects`, `pass_criteria`, `fees`를 반환한다. 각 정보는 `written`, `practical`, `interview`, `phases`, `status`, `source_url`, `retrieved_at`을 포함하며 응시료에는 `currency=KRW`도 포함한다. 기존 필기·실기 필드는 유지했다.

기술사의 필기·면접은 `phases=["written", "interview"]`로 구분하며 면접 값을 실기에 넣지 않는다. 과목·합격기준 원문에 단계 구분 자체가 없으면 `common`에 공식 문구를 보관한다. `common`은 특정 단계의 과목으로 추정한 값이 아니다. 프론트엔드는 단계별 값이 없을 때 common 문구를 그대로 표시할 수 있다.

공식 원문에서 필기시험 없음 또는 실기만 시행하는 검정방법이 확인되면 `phases=["practical"]`로 구분한다. 필기 과목·금액은 null로 유지하지만 시행 단계가 아니므로 partial로 계산하지 않는다. 필기 면제 대상자 여부를 판단하는 기능은 추가하지 않았다.

- `available`: 해당 시험 단계의 값이 모두 확인되거나, 단계 구분 없이 제공된 공식 common 문구를 확보함.
- `partial`: 한 단계만 확인됨.
- `unavailable`: 확인한 값이 없음. 값은 `null`이며 무료나 과목 없음으로 해석하지 않는다.
- 전체 `data_status=complete`: 이번에 제공하는 세 정보의 확인 상태가 모두 available임. common 문구의 단계별 배정을 뜻하지 않으며 응시자격·시험장 등 모든 자격정보의 완성을 뜻하지 않는다.
- `source_type=database`: 저장된 공식 자료 조회. 각 필드의 실제 원본 조회 시각을 그대로 반환한다.

## DB 적용과 실행

이미 기본 테이블이 있는 DB에는 다음 명령으로 상세정보 테이블만 추가한다. 기존 종목·일정·사용자는 유지한다. 같은 명령을 다시 실행하면 기존 상세정보 테이블도 유지한다.

```powershell
.\.venv\Scripts\python.exe -m backend.db.add_exam_information

# 공식 자료 재조회와 미리보기. DB 저장 없음.
.\.venv\Scripts\python.exe -m backend.sync_exam_information

# 확인된 모든 시험정보를 실제 저장.
.\.venv\Scripts\python.exe -m backend.sync_exam_information --apply
```

새 DB는 `backend.db.initialize`가 기본 테이블과 상세정보 테이블을 함께 생성한다. 이미 사용 중인 DB에서 initialize를 다시 실행하지 않는다.

HTTP GET은 DB를 읽기만 한다. 매 조회마다 외부 API를 호출하지 않는다. 최신 자료가 필요하면 동기화 명령을 다시 실행하며 자동 동기화는 아직 설정하지 않았다.

## 오류 가능 지점

통신 실패·시간초과·공식 API 오류는 기존 호출 함수가 처리한다. 최대 1회 재시도 후 동기화는 실패하고 기존 DB 자료는 유지된다. 빈 정상 응답은 재시도하지 않는다. 미수집 종목의 상세 API는 200과 `unavailable`, 존재하지 않는 UUID는 404, DB 연결·테이블 문제는 503을 반환한다.

원문 제목 누락·중복, 읽을 수 없는 단계 표기·금액은 추정하지 않는다. 기본 저장은 세 정보 모두 available일 때만 허용한다. 전체 확대에서는 `--from-report --allow-partial --apply`로 확인한 일부 정보도 저장하며, 미확인 값은 null로 남긴다. 일부 공식 원문에서 면접 검정방법과 실기 합격기준이 충돌하면 실기 문구를 면접으로 바꾸지 않는다.

새 응답이 기존에 확인한 값을 누락하거나 더 오래된 정보이면 기존 행을 유지한다. API 실패로 확보하지 못한 원본은 출처와 조회 시각도 null로 남기며, 나중에 정상 원본으로 갱신할 수 있다. 정상 응답이지만 과목이 없는 경우에는 실제 응답 출처·시각을 보관한다.

## 공식 출처와 검증

- [공식 종목별 자격정보 API](https://www.data.go.kr/data/15003003/openapi.do): 취득방법 원문에서 과목과 기준을 확인한다.
- [공식 국가기술자격 시험정보 API](https://www.data.go.kr/data/15003029/openapi.do): 종목별 응시수수료를 확인한다.
- [정보처리기사 공식 상세 페이지](https://www.q-net.or.kr/crf005.do?id=crf00503s02&jmCd=1320&jmInfoDivCcd=B0): 사용자 확인용 공식 페이지.

현재 키 없이 실제 응답을 받았지만 공식 API 문서는 인증키를 필수로 안내한다. 인증 정책이 달라지면 발급받은 키를 서버 비밀 설정으로 연결하는 작업이 필요하다.

실제 저장 결과는 `research/exam_information_render_sync.json`, DB·HTTP 조회 확인은 `research/exam_information_verification.json`에 기록한다. 변환 테스트는 실제 공식 XML과 잘못된 종목·금액·누락 구간을 사용한다. DB 저장 테스트는 임시 스키마에서 실행한 후 전체 롤백해 검증용 데이터가 남지 않는다.
