JSON의 종목 코드는 문자열이다. `0011` 같은 선행 0을 유지한다. 기술자격 UUID는 이전 Render 저장 결과의 값이며, 새 DB에 넣을 때 그대로 사용할 수 있다는 보장이 없다. **현재 DB의 `qnet_code`로 UUID를 다시 조회**한 후 기존 저장 함수를 사용한다.

전문자격 일정은 계열 단위다. 언어·분야별 종목에 같은 계열 일정이 반환된다고 해서 모든 종목·개별 시험장·개인 시험시간이 확정된 것은 아니다. `first`·`second`를 `written`·`practical`로 추정 변경하지 않는다. 합격자 발표 **시작일**과 조회 가능 **종료일**도 별개로 유지한다.

전문자격 상세 원문·후보 일정·문서 자료는 검토 전이며 DB에 반영하지 않았다. `fetched`는 공식 원본을 받았다는 뜻이다. 세부 과목·응시료 정규화가 완료되었다는 뜻은 아니다. 문서의 `review_status=unreviewed`를 유지한다. 원문이 최신 법령·현재 시행 정보를 반영하는지도 채택 종목별로 확인한다.

대체 HTML 수집은 홈페이지·시험정보 진입 경로 확인 자료다. 페이지 이름이 보이거나 HTTP 200이 반환되어도 실제 일정·상세 본문이 확보되었다고 표시하지 않는다. `usable_information_confirmed=false`를 유지하고 정상 API 원본을 대체하는 정규화 데이터에 자동으로 합치지 않는다.

## 실제 실행 순서

### 1. 준비 데이터를 다시 생성

외부 API와 DB 연결이 필요 없다. 완료된 공식 원본으로 재검증하고 준비 파일을 다시 만든다.

```powershell
.\.venv\Scripts\python.exe -m research.prepare_data
```

흐름은 `보관한 공식 목록 → 기존 Pydantic 모델 검증 → 기술자격 입력 자료 → 전문 계열 날짜 검증 → 누락 작업 목록·문서 자료·원본 해시 저장`이다. 누락 원본·중복 일정·잘못된 기술자격 모델은 오류로 중단한다. 전문 후보의 날짜 오류는 원문을 `professional_schedule_issues.json`에 남기고 후보에서 제외한다.

### 2. 중단된 전문자격 수집을 이어받기

```powershell
.\.venv\Scripts\python.exe -m research.collect_preparation --resume
.\.venv\Scripts\python.exe -m research.prepare_data
```

순서대로 37계열 일정, 100종목 상세를 수집한다. 통신·제공기관 오류는 요청당 최대 1회 재시도한다. 정상 빈 목록은 반복하지 않는다. 각 요청마다 진행 파일을 저장한다. `--resume`은 이미 기록된 실패도 건너뛰므로 종료된 보고서를 무한 재호출하지 않는다.

새로운 전체 갱신이 필요하면 기존 `professional_sources.json`과 `research/responses/preparation_*` 원본을 먼저 별도 보관한 뒤 수집을 새로 시작한다. 기존 결과를 지우고 최신 원문인 것처럼 같은 조회 시각을 쓰지 않는다. 이 수집은 정기 자동 실행을 설정하지 않는다.

공공데이터포털 명세에는 인증키가 필요하다고 적혀 있다. 이번 공개 엔드포인트의 인증 없는 응답 여부는 실제 호출 기록일 뿐 지속적으로 보장되는 계약이 아니다. 운영 연동 시 서비스 활용신청·인증키 조건을 확인한다. [전문자격 일정 공식 API 명세](https://www.data.go.kr/data/15003027/openapi.do)

### 3. 테스트와 실행 환경 확인

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s backend/tests -q
.\.venv\Scripts\python.exe -m unittest research.test_preparation -q
.\.venv\Scripts\python.exe -m pip check
```

프로젝트 `.venv`에 기존 `backend/requirements.txt`의 패키지를 설치했다. 다른 컴퓨터에서는 README의 가상환경 생성·설치 명령을 먼저 실행한다. 현재 확인한 Python은 3.13.15다.

### 4. Render 설정 후 기존 API 실행

```powershell
if (-not (Test-Path backend/.env)) { Copy-Item backend/.env.example backend/.env }
# backend/.env의 DATABASE_URL에 Render External URL(SSL 포함)을 직접 설정한다.
.\.venv\Scripts\python.exe -m backend.db.check
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

기존 DB에는 초기화 SQL을 반복 실행하지 않는다. 설정 파일과 인증키를 Git에 올리지 않는다. 기존 Swagger에서 검색 → 검색 결과 UUID로 상세 → `year=2026` 일정 조회를 확인한다. 새 DB의 종목 UUID는 준비 자료의 과거 UUID와 다를 수 있다.

추천용 `career_tags`는 공식 직무분류와 같은 데이터가 아니다. 팀이 희망 직무와의 관계를 정한 뒤 만든다. 지금 태그나 응시 가능 판정을 임의로 채우지 않았다. 북마크는 기존 주석 상태를 유지하고 로드맵 테이블·API·로직은 만들지 않는다.

범위 회의에서는 대상 기술/전문 종목, 전문자격 포함 여부, AI/RAG 적용 범위, 보류 기능 재개 여부, Google 인증 설정 담당, 프론트·백엔드 API 계약을 확정한다. 데이터 파일은 그대로 활용하고 선택된 범위의 연결 코드부터 작업할 수 있다.

## 남은 데이터 수작업의 처리 기준

- 상세 49종목은 공식 원문에 값이 없는 경우와 단계 표기가 충돌하는 경우를 구분해서 확인한다. 불명확한 값은 `null`로 유지한다.
- 일정 38종목은 상시시험 12, 정기 표 미확인 9, 종목명 대조 실패 17이라는 과거 조사 결과를 참고한다. 현재 시행 여부를 추정하지 않는다.
- 교통산업기사(2751)는 원문에 과목 개편표와 2026년 필기 미시행·실기 회차 안내가 함께 있어 단순한 단계 키워드 추출로 처리하지 않는다.
- 봉제기능사(9776)는 원문에 필기 해당 없음·실기만 시행이라는 문구가 있다. 기존 상세 입력 자료에는 필기 응시료 미확인이 남아 있으므로 단계 구성부터 검토한다.
- 전문자격 API 원문에 과거 연도 문구가 있을 수 있다. 출처가 공식이라는 것과 해당 연도의 내용이 최신이라는 것은 별도로 확인한다.
- 상시시험의 지역·시험장별 일정, 개인 시험시간, 2027년 일정은 이번 파일에서 확보 완료로 표시하지 않는다.

이 준비는 데이터 수집과 정리 비용을 줄이기 위한 작업이다. 현재 서버 배포, 사용자 기능, 전문자격 DB 연동이 완료된 것으로 해석하지 않는다.
