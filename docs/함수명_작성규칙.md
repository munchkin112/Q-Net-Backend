# 팀 함수명 규칙과 적용 결과

기준일: 2026-10-07. 함수명은 영어 소문자와 밑줄을 사용하고 동작을 앞에, 대상을 뒤에 쓴다. 이 문서는 사용자 지정 규칙을 기존 코드에 적용한 범위를 기록한다.

## 기본 규칙

| 역할 | 접두어 | 예시 |
| --- | --- | --- |
| 생성 | create_ | create_user |
| 한 개 조회 | get_ | get_profile |
| 목록 조회 | list_ | list_schedules |
| 수정 | update_ | update_profile |
| 삭제 | delete_ | delete_user |
| 검색 | search_ | search_certificates |
| 외부 API 조회 | fetch_ | fetch_exam_information |
| 화면 표시 | render_ | render_navbar |
| 동작 처리 | handle_ | handle_login |
| 검증 | validate_ | validate_schedule |

이메일·코드 같은 조건은 get_user_by_email, get_certificate_by_code처럼 뒤에 붙인다. 동일 역할은 팀원 간 같은 단어를 사용하며, data·process처럼 대상과 역할이 모호한 이름은 피한다. 원문 추출은 extract_, 원문 해석은 parse_, 수집은 collect_처럼 실제 동작을 표현한다.

## 유지한 이름과 범위

사용자 결정에 따라 save_certificate·save_schedule·save_exam_information·save_profile 등 save_*는 유지한다. 생성과 갱신을 분리하거나 upsert_*로 변경하지 않았다. main·__init__·HTMLParser의 handle_starttag/handle_endtag/handle_data와 Boolean 함수 is_school_exam도 유지한다. 이들은 앞서 제안한 이름 정리 범위에서 제외한다. 그 외 함수명을 일괄 재작성하지 않았다.

HTTP 경로·입출력 필드·DB·수집 규칙은 유지한다. 단, FastAPI가 함수명으로 자동 생성하는 OpenAPI operationId는 변경된다. HTTP 경로를 직접 호출하는 프론트에는 변화가 없으며, OpenAPI 기반으로 생성한 SDK를 사용한다면 새 스키마로 갱신한다.

## 검증

- 백엔드 테스트: 82개 중 79개 통과, 전용 테스트 DB가 필요한 3개 생략.
- 데이터 준비·원문 저장 검증 테스트: 9개 통과.
- 변경 대상 12개와 보존 대상 21개 함수 정의를 이전 커밋과 비교했다. main에서는 새 이름의 함수 호출만 반영했으며 main이라는 이름은 유지했다.
- 실제 Render DB를 사용하는 조회 결과는 [함수명 변경 검증 기록](../research/function_names_verification.json)을 확인한다.

기존 import를 사용하는 팀원은 최신 dev를 받은 뒤 위 새 이름으로 맞춘다. 공개 HTTP 경로는 /certificates, /certificates/{certificate_id}, /certificates/{certificate_id}/schedules를 계속 사용한다.
