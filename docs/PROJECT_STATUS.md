# Q-Net 백엔드 작업 현황과 다음 순서

기준일: 2026-10-05. 실제 코드와 저장·조회 검증 결과를 기준으로 정리했다.

현재는 공식 데이터 수집과 조회 API의 기반을 갖춘 단계다. 전문자격 연동을 확인한 뒤 로그인·프로필을 연결하고 사용자별 기능으로 확장한다.

## 다음 작업: 전문자격 100종목 공식 데이터 연동 조사

1. 공식 API에서 제공하는 상세정보·시험일정과 응답 구조를 확인한다.
2. 대표 종목으로 실제 호출·변환·저장 테스트를 진행한다.
3. 기존 함수를 재사용하고, 필요한 경우 전문자격용 변환만 추가한다.
4. 검증된 범위에서 여러 종목으로 확대하고 미연동 종목과 사유를 기록한다.
5. 전체 DB 구조와 대표 API 응답을 확인한다.

기술자격과 전문자격의 응답 구조가 같다고 가정하지 않는다. 1차·2차 등의 단계는 실제 공식 응답을 확인한 뒤 매핑한다. 목록에 존재한다는 이유로 현재 시행 여부·응시 가능 여부를 확정하지 않는다.

## 이후 진행 순서

| 순서 | 작업 | 진행 기준 |
| --- | --- | --- |
| 1 | 전문자격 상세정보·일정 조사와 연동 확대 | 공식 응답으로 확인한 정보만 저장 |
| 2 | Google 로그인 | 사용자 식별·인증 방식과 Google 설정 확정 |
| 3 | 프로필 HTTP API | 이미 구현한 DB·검증·저장 함수를 인증 사용자와 연결 |
| 4 | AI 기능 | 기존 검색·상세·일정 함수를 tool로 재사용하고 RAG·LangChain·LangGraph 범위를 검토 |
| 5 | 프론트 연동·서버 배포 | 팀의 화면 계약·도메인·환경 설정을 맞추며 단계별 진행 |

자동 갱신과 상시시험은 후속 데이터 운영 과제로 남겨둔다. 응시조건 비교와 Calendar는 별도 재개 결정이 필요하며, 북마크와 로드맵 상태도 위 표를 따른다.

## 검증된 데이터와 API

| 항목 | 결과 |
| --- | --- |
| 공식 목록 | 기술 513 + 전문 100 = 613종목 |
| 상세정보 | 기술자격 510종목, 464종목 전체 확보·46종목 일부 확보 |
| 시험일정 | 475종목·1,922행: 필기 937 / 실기 848 / 면접 137 |
| 미연동 일정 | 상시검정 12 / 정기 일정 미확인 9 / 종목명 대조 실패 17 |
| 데이터 보존 | 기존 36개 일정 ID·확인된 날짜 유지, 중복 키 0 |
| 기본 자동 테스트 | 82개 중 79개 통과, 전용 DB 설정이 필요한 3개 생략 |
| DB 통합 검증 | Render 임시 스키마에서 프로필·단계 분리·새 일정 마이그레이션 검증 후 롤백 |
| 실제 조회 검증 | 상세정보 대표 16종목, 일정 대표 12종목, 전체 저장 데이터 모델 검증 |

조회 API는 `/health`, `/health/database`, `/api/v1/certificates`, `/api/v1/certificates/{certificate_id}`, `/api/v1/certificates/{certificate_id}/schedules?year=2026`이다. Swagger는 서버 실행 후 [로컬 문서](http://127.0.0.1:8000/docs)에서 확인한다.

## 개발 브랜치 운영

`dev`에서 현재 개발 결과를 공유하고 팀원이 내려받아 검토한다. 기능별 작업은 별도 브랜치에서 진행하고 PR로 dev에 반영한다. 검증된 배포 버전을 main에 반영한다. 구체적인 리뷰·머지 정책은 팀과 결정한다.

GitHub에는 코드·설계·테스트·공식 데이터 검증 자료를 공유한다. Render에 저장된 실제 데이터는 별도 DB이며 Git push가 DB를 배포하거나 초기화하는 것은 아니다.
