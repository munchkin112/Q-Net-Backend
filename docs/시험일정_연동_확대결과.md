## 코드와 데이터 처리

일정 API의 시간초과·제공기관 오류가 반복되어 공식 종목 페이지를 직접 수집하는 별도 명령을 추가했다. HTML을 실행하지 않고 7열 일정 표를 읽는다. 기존 `normalize_technical_schedules`, `ScheduleInput`, `save_schedule`, 일정 조회 API를 재사용하며 일반 함수·조건문·반복문을 중심으로 구현했다.

1. `backend.sync_schedule_pages`: 513종목의 원본 HTML·출처·실제 조회 시각 확보.
2. `backend.official_schedule_page`: 표 해석 → 필기/실기/면접으로 분리 → 기존 날짜 검증.
3. `backend.apply_schedule_pages`: 보관한 원본 검증 → 같은 종목의 모든 단계 저장을 한 트랜잭션으로 확정.
4. `research.verify_schedule_expansion`: 전체 DB 모델·중복·기존 ID·날짜와 실제 API 검증.

기술사 면접은 `interview`로 저장한다. 셀 닫는 태그가 생략된 공식 표도 읽으며, 실기 단독 회차와 수시 시험의 원래 회차명을 보존한다. 필기·실기·면접은 각각 다른 일정 ID를 가진다. 일반인 응시 불가로 명시된 특성화고 등의 필기면제자 검정은 일반 일정에 합치지 않는다.

`registration_periods` JSONB를 추가했다. 각 항목은 `starts_on`, `ends_on`, `source_url`, `retrieved_at`이다. 실제 접수 가능 날짜는 이 목록으로 표시한다. `registration_start/end`는 전체 범위이며 그 사이의 모든 날짜가 접수 가능하다는 뜻이 아니다.

기술사 면접의 두 접수기간은 종목 페이지에서 읽었다. 2026년 기사 3회 실기 접수는 9/21~9/23, 9/28로 나눴다. 이 예외는 [2026년도 공식 시행공고 제2025-208호](https://www.kosca21.or.kr/km_board/upload/km_b_notice/1765809270_01.pdf) PDF 2쪽에서 확인했고, 해당 기간의 출처·조회 시각에 공고 정보를 남겼다. 기술사 합격회차에 따른 접수 제한, 접수 시간과 개인 시험장 배정은 공식 공고에서 별도 확인해야 한다. 응시조건 비교는 구현하지 않았다.

원문에 없는 기존 결과조회 종료일을 지우지 않기 위해 15개 행의 전체 자료를 유지했다. 이 행들은 접수 범위가 일치할 때 접수기간 목록만 자체 출처와 함께 보완했다. 원래 일정의 출처·조회 시각은 유지했다. 나머지 1,907행은 새 원본으로 저장·갱신했다. 실패·빈 일정 때문에 기존 행을 삭제하지 않는다.

## Swagger와 DBeaver 확인

[로컬 Swagger](http://127.0.0.1:8000/docs)에서 자격증 검색으로 UUID를 얻고, 시험일정 API의 `certificate_id`와 `year=2026`에 입력한다. 기존 목록 응답 형태를 유지하며 `interview`, `registration_periods`, 빈자리 접수기간을 확인할 수 있다. 빈 응답은 수집된 일정이 없다는 뜻이다.

DBeaver에서 `Schemas → public → Tables → schedules`를 새로고침하고 Data 탭을 연다. `registration_periods` 컬럼이 안 보이면 테이블 메타데이터도 새로고침한다. SQL 편집기에서는 다음 조회로 종목명과 일정을 함께 볼 수 있다.

```sql
SELECT c.qnet_code, c.name, s.round_label, s.phase,
       s.registration_periods, s.exam_start, s.exam_end, s.result_date,
       s.vacancy_registration_start, s.vacancy_registration_end
FROM certificates AS c
JOIN schedules AS s ON s.certificate_id = c.id
WHERE s.year = 2026
ORDER BY c.name, s.round_key, s.phase;
```

## 검증과 원본

자동 테스트 82개 중 79개 통과, 테스트 DB 설정이 필요한 3개는 기본 실행에서 생략했다. Render 임시 스키마에서 기존 프로필·단계 분리 테스트와 새 일정 마이그레이션 테스트를 별도로 통과했고 전체 롤백했다. 새 마이그레이션은 반복 적용, 기존 ID·날짜 유지, 두 접수기간 JSON 저장, 정보 보존, 오래된 기간의 덮어쓰기 차단과 종목별 롤백을 검증했다.

실제 저장된 1,922행 전체의 응답 모델 검증을 통과했다. 대표 12종목의 실제 HTTP 조회와 health·DB 상태·Swagger·OpenAPI는 모두 200이었다. 정보처리기사의 두 접수기간, 금형기술사 면접, 기계가공기능장, 컴퓨터응용밀링기능사, 석공기능사의 실기 단독, 공공조달관리사의 수시 회차, 상시·빈 일정·종목명 미확인 응답을 확인했다.
